# 审计OCR识别与知识库匹配优化方案

## 一、现状问题分析

### 1.1 数据识别质量问题

| 问题类型 | 占比 | 说明 |
|---------|------|-----|
| 金额字段为空 | ~50% | 大量发票/收据的total_amount识别为N/A |
| 图片类型识别错误 | 部分 | "其他"类型占比过高（36条） |
| 知识库匹配质量差 | 普遍 | 匹配规则ID固定，缺乏针对性 |

### 1.2 当前知识库统计

- **总记录数**：50条
- **分类数量**：2个
- **规则粒度**：过粗，仅按凭证大类划分

### 1.3 识别为空的重灾区

| 图片类型 | 样本数 | 金额为空数 | 问题分析 |
|---------|--------|-----------|---------|
| 其他 | 36 | 32 | 类型判断失败，无法提取结构化信息 |
| 开户许可证 | 12 | 12 | **正常**，此类凭证无金额字段 |
| 公章 | 16 | 16 | **正常**，印章类凭证无金额 |
| 飞机票 | 19 | 13 | **严重问题**，机票应有金额 |
| 营业执照 | 10 | 10 | **严重问题**，营业执照有注册资本 |
| 报销单 | 11 | 11 | **正常**，报销单格式多样难识别 |
| 在建工程现场照片 | 8 | 8 | **正常**，照片类凭证无金额 |

---

## 二、问题根因分析

### 2.1 知识库问题

1. **规则数量不足**：仅50条规则无法覆盖100+种凭证类型
2. **规则粒度太粗**：按凭证大类划分，缺乏具体票种的详细规则
3. **匹配策略单一**：仅用"审计凭证OCR识别 {文件名}"作为query，难以准确匹配
4. **缺乏领域知识**：没有针对中国发票特点的专项规则（如增值税专用发票校验规则）

### 2.2 OCR识别问题

1. **图片类型判断不准确**：将大量不同凭证误判为"其他"
2. **结构化提取能力弱**：模型对非标准格式凭证的字段提取能力不足
3. **金额转换不完整**：繁体中文数字转换逻辑可能存在遗漏

### 2.3 提示词工程问题

1. **通用提示词**：未针对不同凭证类型使用专门的提取提示词
2. **知识库检索query质量差**：仅用文件名作为query，无法有效检索相关规则

# 增值税发票校验规则

## 增值税专用发票校验规则

### 规则1：发票代码校验
- 规则ID: INV-001
- 规则内容: 增值税专用发票代码为10位，第1-4位为地区编码，第5-6位为年份，第7位为批次，第8位为发票类型（1=专用发票），第9位为联次，第10位为版本
- 风险等级: 中风险
- 校验逻辑: 正则 `^\\d{10}$`

### 规则2：发票号码校验
- 规则ID: INV-002
- 规则内容: 发票号码为8位
- 风险等级: 低风险

### 规则3：价税合计金额校验
- 规则ID: INV-003
- 规则内容: 价税合计 = 金额 + 税额，金额 = 价税合计 / (1 + 税率)
- 风险等级: 高风险
- 触发条件: 识别到的金额与计算的金额差异超过1元

### 规则4：开票日期有效期校验
- 规则ID: INV-004
- 规则内容: 增值税专用发票应在开具之日起180日内认证抵扣
- 风险等级: 高风险
- 触发条件: 开票日期距今超过180天

### 规则5：销方税号与购买方税号一致性
- 规则ID: INV-005
- 规则内容: 同一张发票的销方税号和购买方税号不能相同
- 风险等级: 高风险

...（继续补充更多规则）
```

# 凭证类型识别指南

## 航空运输电子客票行程单

### 识别要点
1. **票面特征**：
   - 纸质行程单（蓝灰色底纹）
   - 右上角有"航空运输电子客票行程单"字样
   - 有旅客姓名、航班号、出发地/目的地、日期、票价等信息

2. **关键字段**：
   - 旅客姓名
   - 航班号（2位字母+4位数字，如CA1234）
   - 出发地/目的地机场三字码
   - 起飞/到达时间
   - 票价（非民航发展基金）
   - 税款（民航发展基金 + 燃油附加费）

3. **金额识别规则**：
   - **票价**：行程单上标注的"票价"字段
   - **实际金额** = 票价 + 民航发展基金 + 燃油附加费
   - 注意：行程单金额可能包含多项，需全部加总

### 风险点
- 行程单可能存在伪造
- 日期可能在180天有效期外
- 金额与实际行程不符
```

#### 3.2.1 分类优化：减少"其他"类型占比

**目标**：将"其他"类型占比从当前比例降至10%以下

**方案**：

3. 对被判断为"其他"的凭证，增加二次识别逻辑

#### 3.2.2 金额识别强化

**针对问题类型**：
- 飞机票：应识别票价 + 民航发展基金 + 燃油附加费
- 营业执照：应识别注册资本金额
- 火车票：应识别票价

**优化提示词**：
```markdown
### 金额识别强制要求（针对不同票种）

**飞机票/行程单**：
- 必须识别"票价"字段（非票价总额）
- 需加总：票价 + 民航发展基金(¥50) + 燃油附加费
- 示例：票价¥800 + 民航发展基金¥50 + 燃油费¥120 = ¥970

**火车票**：
- 识别"票面金额"或"票价"字段
- 示例：¥553.00

**收据/小票**：
- 识别"实收金额"或"合计"字段
- 注意区分原价和优惠价
```

### 3.4 知识库导入脚本优化

**优化方向**：
1. 解析时保留更完整的上下文信息
2. 自动识别规则适用的凭证类型
3. 生成更精准的embedding文本

```python
# 优化后的embedding生成
def generate_embedding_text(chunk):
    parts = [
        f"凭证类型：{chunk.get('applicable_types', '通用')}",
        f"规则名称：{chunk['rule_name']}",
        f"规则内容：{chunk['content']}",
        f"风险等级：{chunk['risk_level']}",
        f"适用场景：{chunk.get('scene', '')}"
    ]
    return " | ".join([p for p in parts if p])
```
