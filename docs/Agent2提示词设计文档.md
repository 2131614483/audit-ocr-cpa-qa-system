# Agent2 提取提示词设计文档

## 一、设计概述

Agent2 是双级Agent管道中的第二级，负责从已分类的凭证图片中提取关键字段信息。提示词系统围绕"让视觉语言模型准确理解凭证结构并提取结构化数据"这一核心目标设计。

### 设计原则

1. **分层结构化**：大类模板 → 具体类型指引 → 提取规则 → 输出示例，层层递进
2. **视觉引导**：为每种凭证类型描述视觉特征，帮助模型定位关键信息
3. **规则明确**：金额、日期、文本的处理规则精确到具体格式
4. **示例驱动**：提供4个典型输出示例，让模型理解期望的输出格式
5. **容错机制**：允许模型提取参考字段之外的信息，并在图片与类型不符时说明

## 三、第1层：凭证信息与视觉识别指引

### 3.1 设计思路

每种凭证类型都有独特的视觉特征（颜色、布局、关键字段位置）。通过描述这些特征，帮助模型快速定位关键信息区域，减少误识别。

### 3.2 数据来源

`TYPE_VISUAL_GUIDANCE` 字典，覆盖全部130种凭证类型，按10大类分组。

### 3.3 编写示例

```python
# 发票类示例
"增值税专用发票": "通常为黄色或绿色底纹，左上角有'增值税专用发票'字样，右侧有发票联/抵扣联标识。包含购销双方名称、税号、金额、税额、价税合计等关键信息。注意区分密码区和备注栏。"

# 银行类示例
"银行回单": "银行交易回单格式，有'业务回单'或'电子回单'字样。包含交易日期、收款人、付款人、金额、摘要、交易流水号。注意区分贷方回单和借方回单。"

# 报表类示例
"资产负债表": "资产负债表格式，有'资产负债表'标题。包含资产（流动资产/非流动资产）、负债（流动负债/非流动负债）、所有者权益各项目金额及合计。提取主要项目金额。"
```

### 3.4 编写要点

- 描述颜色、标题文字等显著视觉特征
- 指出关键信息的位置（左上角、右侧等）
- 列出该类型特有的字段
- 提示容易混淆的地方（如区分贷方/借方回单）
- 对于跨大类的相同类型（如"航空运输电子客票"同时属于发票类和差旅类），使用"同XX类，已在上方定义"避免重复

## 四、第2层：参考字段列表

### 4.1 设计思路

字段列表是模型提取的"锚点"，告诉模型应该关注哪些字段。采用三级回退策略确保总有可用的字段模板。

### 4.2 三级回退策略

```
第1级：数据库 document_types.expected_fields
  → 最精确，每个类型独立配置
  → 当前数据库中130种类型都有模板字段

第2级：FIELD_TEMPLATES（10大类模板）
  → 当数据库没有配置时使用
  → 每个大类5-10个字段，覆盖该类别常见字段

第3级：默认3个通用字段
  → 兜底方案
  → amount, date, description
```

### 4.3 10大类字段模板（优化后）

| 大类 | 字段数 | 新增字段 |
|------|--------|---------|
| 发票类 | 10个 | +buyer_tax_id, +seller_tax_id |
| 差旅票据类 | 7个 | +transport_type, +seat_class |
| 银行/资金类 | 8个 | +summary, +balance |
| 函证/审计类 | 6个 | +project_name |
| 税务类 | 6个 | +tax_authority |
| 企业内部管理类 | 6个 | +approver |
| 薪酬/人事/合同类 | 5个 | +id_number |
| 账簿/分录/报表类 | 6个 | +company_name |
| 固定资产/成本类 | 6个 | +dept_name |
| 收据/合同/资质类 | 7个 | +party_a, +party_b |

相比优化前，每个大类增加了1-3个字段，使模板更完整。

## 五、第3层：提取规则

### 5.1 设计思路

视觉语言模型在处理数字和日期时容易出错（如保留货币符号、日期格式不一致）。通过明确的规则约束，规范模型输出。

### 5.2 金额字段处理规则

```
- 只提取纯数字，去掉货币符号（¥、$、€等）
- 保留小数点后两位（如 1234.56）
- 千分位分隔符要去掉（如 1,234.56 → 1234.56）
- 金额范围用连字符（如 1000-2000）
- 大写金额不提取，只提取阿拉伯数字金额
```

**设计原因**：视觉模型经常把"¥1,234.56"直接输出为字符串，导致后续无法做数值计算。明确要求去掉符号和分隔符。

### 5.3 日期字段处理规则

```
- 统一格式为 YYYY-MM-DD
- 如看到"2024年3月5日" → "2024-03-05"
- 如看到"24.3.5" → "2024-03-05"
- 如看到"2024/3/5" → "2024-03-05"
- 只有年份和月份时用 YYYY-MM（如 "2024-03"）
- 只有年份时用 YYYY（如 "2024"）
```

**设计原因**：中文日期格式多样（年月日、点号分隔、斜杠分隔），统一为标准ISO格式便于数据库存储和比较。

### 5.4 文本字段处理规则

```
- 保留原文内容，不要改写
- 去除首尾空格
- 多行文本用空格连接成一行
- 英文统一使用小写（专有名词除外）
```

### 5.5 字段名命名规则

```
- 使用英文小写+下划线
- 通用字段名：amount, date, description, name, code, number
- 业务字段名：invoice_code, buyer_name, seller_name, tax_amount 等
- 不要使用中文作为字段名
```

### 5.6 置信度评分标准（5档）

| 置信度范围 | 含义 | 适用场景 |
|-----------|------|---------|
| 0.95-1.00 | 文字清晰可见，所有字段都能准确识别 | 高质量扫描件、电子发票 |
| 0.80-0.94 | 大部分文字清晰，个别字段可能有模糊 | 普通拍照图片 |
| 0.60-0.79 | 部分文字模糊或遮挡，核心字段可识别 | 角度倾斜、光线不佳 |
| 0.40-0.59 | 图片质量差，只能识别少量信息 | 严重模糊、反光 |
| 0.00-0.39 | 几乎无法识别，仅能猜测 | 极低质量图片 |

**设计原因**：让模型对自己的识别结果进行评分，后续审计规则可以根据置信度决定是否自动通过或需要人工复核。

## 六、第4层：输出示例

### 6.1 设计思路

Few-shot示例是提示词工程中最有效的手段之一。通过展示4个典型凭证的输出格式，让模型理解：
1. 字段名应该用什么格式（英文小写+下划线）
2. 字段值应该怎么格式化（金额去符号、日期标准化）
3. 元数据字段（_confidence, _summary）的用法

### 6.2 4个示例的选择理由

| 示例 | 凭证类型 | 所属大类 | 选择理由 |
|------|---------|---------|---------|
| 示例1 | 增值税专用发票 | 发票类 | 最常用的凭证类型，字段多且结构化 |
| 示例2 | 银行回单 | 银行/资金类 | 金额+方向+余额的组合 |
| 示例3 | 费用报销单 | 企业内部管理类 | 文本字段为主，展示description用法 |
| 示例4 | 记账凭证 | 账簿/分录/报表类 | 借方/贷方金额的展示 |

## 七、代码实现

### 7.1 函数：`build_extract_prompt`

```python
def build_extract_prompt(doc_type_name: str, category_name: str) -> str:
    # 1. 获取字段模板（三级回退）
    db_fields = get_expected_fields(doc_type_name)
    if db_fields:
        fields = db_fields
    else:
        fields = FIELD_TEMPLATES.get(category_name, [])
        if not fields:
            fields = [{"name": "amount", ...}, ...]

    # 2. 格式化字段列表
    field_list = "\n".join([f'    "{f["name"]}": "{f["label"]}"' for f in fields])

    # 3. 获取视觉线索
    visual_guide = TYPE_VISUAL_GUIDANCE.get(doc_type_name, "默认指引")

    # 4. 组装完整提示词（4层结构）
    prompt = f"""
    ## 凭证信息
    ...
    ## 视觉识别指引
    {visual_guide}
    ## 参考字段
    {field_list}
    {EXTRACTION_RULES}
    {OUTPUT_EXAMPLES}
    ## 输出要求
    ...
    """
    return prompt
```

### 7.2 数据流

```
输入: doc_type_name + category_name
  │
  ├─→ get_expected_fields(doc_type_name)  ← 数据库查询
  │     └─→ 有结果? → 使用数据库字段模板
  │
  ├─→ FIELD_TEMPLATES[category_name]      ← 内存字典
  │     └─→ 有结果? → 使用大类模板
  │
  ├─→ 默认3个字段                          ← 兜底
  │
  ├─→ TYPE_VISUAL_GUIDANCE[doc_type_name] ← 视觉线索
  │
  ├─→ EXTRACTION_RULES                    ← 提取规则
  │
  └─→ OUTPUT_EXAMPLES                     ← 输出示例
       │
       └─→ 组装为完整提示词 → 发送给LLM
```

## 九、使用说明

### 9.1 修改字段模板

编辑 `FIELD_TEMPLATES` 字典，按大类添加或修改字段：

```python
FIELD_TEMPLATES["发票类"].append({
    "name": "new_field",
    "type": "text",      # text / amount / date
    "label": "新字段名称"
})
```

### 9.2 修改视觉指引

编辑 `TYPE_VISUAL_GUIDANCE` 字典，按凭证类型名称修改：

```python
TYPE_VISUAL_GUIDANCE["增值税专用发票"] = "新的视觉描述..."
```

### 9.3 修改提取规则

编辑 `EXTRACTION_RULES` 字符串，按Markdown格式修改。

### 9.4 修改输出示例

编辑 `OUTPUT_EXAMPLES` 字符串，按Markdown格式修改。

## 十、注意事项

1. **提示词长度**：优化后的提示词约1500-2000 tokens（含视觉指引），在qwen3.5:9b的32K上下文窗口内
2. **视觉指引的准确性**：视觉指引是人工编写的，如果实际图片与描述不符，模型可能产生混淆
3. **字段模板的优先级**：数据库字段 > 大类模板 > 默认字段，修改数据库中的expected_fields会立即生效
4. **置信度的校准**：不同模型对置信度的理解可能不同，建议定期校准评分标准
5. **跨大类类型**：某些类型（如航空运输电子客票）同时属于多个大类，视觉指引中通过引用避免重复
