## 四、审计 OCR 识别流程

### 4.1 核心函数调用链

```
main.py
  └─→ choose_provider()            # 交互选择模型供应商
  └─→ choose_mode()                # 选择模式：完整审计 / 多模型并发 / 重跑
      └─→ batch_audit_process()    # 遍历图片文件夹
          └─→ audit_ocr_recognize()  # 单张图片识别
              ├─→ call_llm()         # 调用大模型视觉识别
              │    ├─ ollama → _call_ollama()
              │    └─ 其他API → _call_openai_compat()
              ├─→ fix_json_with_deepseek()  # JSON解析失败时修复
              ├─→ safe_json_loads()         # 安全JSON解析
              ├─→ retrieve_relevant_rules() # 知识库检索
              ├─→ deep_merge()              # 合并默认值与识别结果
              └─→ [返回结构化结果]
```

### 4.2 Prompt 设计

OCR 识别的 system prompt 位于 `ocr_engine.py` 的 `audit_ocr_recognize()` 函数中，包含：

1. **角色设定**：审计专家，精通各类凭证识别
2. **票据类型列表**：从 `config/constants.py` 的 `IMAGE_TYPES` 动态注入
3. **输出格式要求**：严格 JSON 结构，含 ocr_extract / validation_result / risk_rating 等字段
4. **知识库注入**：检索到的 top-5 知识库规则拼入 prompt

### 4.3 JSON 修复机制

当主模型返回的 JSON 解析失败时，触发修复流程：

```
原始响应 → safe_json_loads() 失败
    │
    ▼
fix_json_with_deepseek(raw_content, image_path, rules_text)
    │  使用 DeepSeek 模型修复格式
    │  最多重试 3 次 (FIX_RETRY_TIMES)
    │
    ├──→ 成功 → 返回修复后 JSON
    └──→ 失败 → 返回 FALLBACK_RESULT（标记为高风险/不通过）
```

### 4.4 数据校验规则

定义在 `services/validator.py`：

| 校验项 | 函数 | 规则 |
|--------|------|------|
| 日期 | is_valid_date() | 格式 YYYY-MM-DD，不超过当前时间 |
| 金额 | is_valid_amount() | 非负，最多2位小数，支持中文大写金额 |
| 信用代码 | is_valid_credit_code() | 18位数字+大写字母格式 |

## 六、审计 AI 辅导流式机制

### 6.1 SSE 协议

采用 Server-Sent Events 标准协议：

```
Content-Type: text/event-stream

data: {"type":"meta","cpa_referenced":[...]}

data: {"type":"token","content":"..."}

data: {"type":"done"}
```

### 6.2 前端流式接收

```javascript
// 使用 ReadableStream API
fetch('/api/ask_ai_stream', { method: 'POST', body: JSON.stringify(payload) })
    .then(response => {
        const reader = response.body.getReader();
        const decoder = new TextDecoder();
        let buffer = '';
        
        function readChunk() {
            reader.read().then(({ done, value }) => {
                buffer += decoder.decode(value, { stream: true });
                const lines = buffer.split('\n');
                buffer = lines.pop() || '';
                
                for (const line of lines) {
                    if (line.trim().startsWith('data: ')) {
                        const event = JSON.parse(line.trim().slice(6));
                        if (event.type === 'token') {
                            // 实时渲染 Markdown
                            contentDiv.innerHTML = marked.parse(fullAnswer);
                        }
                    }
                }
                readChunk();
            });
        }
        readChunk();
    });
```

### 6.3 代理转发

审计仪表盘 (app.py) 不直接调用 DeepSeek，而是通过 HTTP 代理转发到 CPA 问答服务 (web_app.py)：

```
前端 → app.py:5000/api/ask_ai_stream → web_app.py:5001/api/audit_tutor_stream
                                                           ↓
                                              search_knowledge_base() 检索教材
                                                           ↓
                                              call_deepseek_stream() 流式生成
                                                           ↓
                                              SSE 流返回
```

class AppConfig:

        if cls._instance is None:
            cls._instance = super().__new__(cls)
            raw = load_config(config_path)  # 合并默认值 + config.json
            for k, v in raw.items():
                setattr(cls._instance, k, v)

## 九、扩展指南

### 9.1 添加新的审计知识库规则

1. 编辑 `knowledge/audit_knowledge_base.json`，在对应 category 下添加新规则
2. 运行入库脚本：
   ```bash
   python knowledge/import_knowledge_base.py
   ```

### 9.2 添加新的 CPA 教材

1. 将教材的 `_noimg.md` 文件放入 `cpazs/{教材名称}/auto/` 目录
2. 在 `cpazs/config_cpa.py` 的 `DATA_SOURCES` 列表中添加新条目
3. 重新运行导入：
   ```bash
   python clear_embeddings.py
   python import_all_cpa_8b.py
   ```

### 9.3 添加新的模型供应商

1. 在 `data/model_config.json` 的 `providers` 中添加新供应商配置
2. 在 `services/ollama_client.py` 的 `call_llm()` 函数中处理新供应商的 API 格式
3. 在 `services/embedding_service.py` 中处理新供应商的 Embedding API

### 9.4 添加新的票据类型

编辑 `config/constants.py` 的 `IMAGE_TYPES` 列表即可。

## 十、常见问题与调试

### 10.1 端口被占用

```bash
# 查看端口占用
netstat -ano | findstr :5000
netstat -ano | findstr :5001

# 强制结束进程
taskkill /PID <PID> /F
```

### 10.2 Ollama 连接失败

```bash
# 检查 Ollama 是否运行
curl http://localhost:11434/api/tags

# 启动 Ollama
ollama serve
```

### 10.3 PostgreSQL 连接失败

检查 `data/config.json` 中的数据库配置是否正确：

```json
{
    "DB_HOST": "localhost",
    "DB_PORT": 5432,
    "DB_NAME": "audit_ocr",
    "DB_USER": "postgres",
    "DB_PASSWORD": "admin"
}
```

### 10.4 调试模式

所有服务默认以 `debug=True` 启动，当发生错误时会显示 Werkzeug 调试器页面，包含完整的堆栈跟踪和代码上下文。

### 10.5 开启日志

错误日志位于 `output/ocr_error_simple.log`，重跑任务日志位于 `output/ocr_retry_tasks.log`。
