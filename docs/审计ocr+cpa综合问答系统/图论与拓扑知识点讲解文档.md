## 1. 图论基础概念

### 1.1 图的定义与分类

**图（Graph）** 是由顶点（Vertex）和边（Edge）组成的数据结构，记为 `G = (V, E)`：

- **顶点（Vertex/Node）**：表示实体、概念或对象
- **边（Edge/Link）**：表示顶点之间的关系或连接

**图的分类：**

| 类型 | 定义 | 项目应用 |
|------|------|----------|
| **有向图** | 边有方向（A→B ≠ B→A） | 知识图谱关系（如"属于"、"引用"） |
| **无向图** | 边无方向（A-B = B-A） | 社交网络、无向连接 |
| **加权图** | 边带有权重 | 关系置信度（confidence）、重要性（weight） |
| **异构图** | 顶点和边有不同类型 | CPA知识图谱（Concept、Standard、Formula等） |

**项目中的图模型：**

```
顶点类型（Entity Type）：
├── Concept（概念）：如"注册会计师行业"、"独立性原则"
├── Standard（准则）：如"审计准则"、"会计准则"
├── Formula（公式）：如"资产=负债+所有者权益"
├── TaxItem（税目）：如"增值税"、"企业所得税"
└── Question（考题）：CPA考试真题

边类型（Relation Type）：
├── composes（组成）：A由B组成
├── belongs_to（属于）：A属于B
├── references（引用）：A引用B
├── derives_from（派生）：A派生自B
├── contrasts_with（对比）：A与B对比
├── leads_to（导致）：A导致B
└── prerequisite_of（前提）：A是B的前提
```

### 1.2 图的存储结构

项目中使用 **邻接表（Adjacency List）** 存储图：

```python
# 出边表：{源节点: [(目标节点, 关系类型, 权重, 描述)]}
_adj_out = {
    1: [(2, "composes", 1.0, "注册会计师行业由财会监督组成"), ...],
    2: [(3, "references", 0.95, "财会监督引用审计准则"), ...],
}

# 入边表：{目标节点: [(源节点, 关系类型, 权重, 描述)]}
_adj_in = {
    2: [(1, "composes", 1.0, "注册会计师行业组成财会监督"), ...],
    3: [(2, "references", 0.95, "财会监督引用审计准则"), ...],
}

# 实体属性表：{节点ID: {name, entity_type, category, definition}}
_entities = {
    1: {"name": "注册会计师行业", "entity_type": "Concept", ...},
    2: {"name": "财会监督", "entity_type": "Concept", ...},
}
```

**邻接表 vs 邻接矩阵：**

| 对比项 | 邻接表 | 邻接矩阵 |
|--------|--------|----------|
| 空间复杂度 | O(V + E) | O(V²) |
| 适用场景 | 稀疏图（边数少） | 稠密图（边数多） |
| 遍历效率 | 高 | 低 |
| 项目选择 | ✅ 推荐 | ❌ |

### 1.3 图的基本性质

- **度（Degree）**：节点连接的边数
  - 出度（Out-degree）：从该节点出发的边数
  - 入度（In-degree）：指向该节点的边数

- **路径（Path）**：从节点A到节点B经过的边序列
  - 路径长度：边的数量
  - 简单路径：不重复经过同一节点的路径

- **连通性（Connectivity）**：
  - 连通图：任意两节点之间存在路径
  - 强连通：有向图中任意两节点双向可达

## 2. 核心图论算法

### 2.1 广度优先搜索（BFS）

**原理：** 从起点开始，逐层扩展邻居节点，使用队列（Queue）实现。

**应用场景：**
- 知识图谱多跳检索
- 实体邻域展开
- 最短路径查找

**项目实现：** [services/kg_traversal.py](file:///d:/pythonpro/ollama项目/审计OCR+CPA问答综合系统/services/kg_traversal.py#L58-L120)

```python
def bfs(self, start_ids: list, max_depth: int = 3, 
        relation_types: list = None, max_results: int = 100) -> list[dict]:
    """BFS多跳遍历"""
    self.load_graph()
    
    visited = {}  # {entity_id: (depth, prev_id, relation_type)}
    queue = deque()
    
    # 初始化队列
    for sid in start_ids:
        if sid in self._entities:
            visited[sid] = (0, None, None)
            queue.append(sid)
    
    while queue:
        current = queue.popleft()
        depth = visited[current][0]
        
        if depth >= max_depth:
            continue
        
        # 遍历出边
        for neighbor in self._adj_out.get(current, []):
            tgt_id, rtype, weight, desc = neighbor
            if relation_types and rtype not in relation_types:
                continue
            if tgt_id not in visited:
                visited[tgt_id] = (depth + 1, current, rtype)
                queue.append(tgt_id)
                if len(visited) >= max_results:
                    queue.clear()
                    break
        
        # 遍历入边（反向）
        for neighbor in self._adj_in.get(current, []):
            src_id, rtype, weight, desc = neighbor
            if relation_types and rtype not in relation_types:
                continue
            if src_id not in visited:
                visited[src_id] = (depth + 1, current, f"<-{rtype}")
                queue.append(src_id)
                if len(visited) >= max_results:
                    queue.clear()
                    break
    
    # 构建结果
    results = []
    for eid, (depth, prev, rel) in visited.items():
        if eid not in self._entities:
            continue
        ent = self._entities[eid]
        results.append({
            "entity_id": eid,
            "name": ent["name"],
            "entity_type": ent["entity_type"],
            "depth": depth,
            "path": self._reconstruct_path(eid, visited),
        })
    return results
```

**关键要点：**
1. 使用 `deque` 实现高效队列操作
2. `visited` 字典记录深度、前驱节点和关系类型
3. 同时遍历出边和入边实现双向扩展
4. 支持关系类型过滤和结果数量限制

### 2.3 最短路径算法（双向BFS）

**双向BFS（Bidirectional BFS）**

**原理：** 同时从起点和终点进行BFS，当两个搜索前沿相遇时找到最短路径。

**项目实现：** [services/kg_traversal.py](file:///d:/pythonpro/ollama项目/审计OCR+CPA问答综合系统/services/kg_traversal.py#L139-L205)

```python
def find_paths(self, source_name: str, target_name: str,
               max_depth: int = 5) -> list[list[dict]]:
    """双向BFS查找最短路径"""
    self.load_graph()
    
    source_id = self._find_entity_id(source_name)
    target_id = self._find_entity_id(target_name)
    if not source_id or not target_id:
        return []
    
    # 双向BFS
    forward = {source_id: (None, None)}   # 前向搜索
    backward = {target_id: (None, None)}  # 后向搜索
    f_queue = deque([source_id])
    b_queue = deque([target_id])
    
    paths = []
    depth = 0
    found = False
    
    while depth < max_depth and not found:
        depth += 1
        
        # 扩展前向
        f_next = set()
        for current in list(f_queue):
            for neighbor in self._adj_out.get(current, []):
                tgt, rtype, _, _ = neighbor
                if tgt not in forward:
                    forward[tgt] = (current, rtype)
                    f_next.add(tgt)
                    if tgt in backward:
                        paths = self._merge_paths(source_id, tgt, target_id,
                                                  forward, backward)
                        found = True
                        break
        f_queue = deque(f_next)
        
        if found:
            break
        
        # 扩展后向（类似）
        b_next = set()
        ...
    
    return paths
```

**路径合并：** [services/kg_traversal.py](file:///d:/pythonpro/ollama项目/审计OCR+CPA问答综合系统/services/kg_traversal.py#L207-L234)

```python
def _merge_paths(self, source_id: int, meet_id: int, target_id: int,
                 forward: dict, backward: dict) -> list[list[dict]]:
    """合并双向BFS的路径"""
    # 从前向构建到meeting点
    f_path = []
    cur = meet_id
    while cur is not None:
        f_path.append({"entity_id": cur, "name": self._entities.get(cur, {}).get("name", str(cur))})
        if cur in forward:
            cur = forward[cur][0]
        else:
            break
    f_path.reverse()
    
    # 从后向构建
    b_path = []
    cur = meet_id
    if cur in backward:
        cur = backward[cur][0]
    while cur is not None:
        b_path.append({"entity_id": cur, "name": self._entities.get(cur, {}).get("name", str(cur))})
        if cur in backward:
            cur = backward[cur][0]
        else:
            break
    
    full_path = f_path + b_path
    return [full_path]
```

**双向BFS的优势：**
- 时间复杂度：O(b^(d/2))，其中b是平均分支因子，d是最短路径长度
- 相比单向BFS的O(b^d)，在路径较长时效率提升显著

### 2.4 子图展开

**原理：** 以指定实体为中心，按深度展开其邻域子图。

**项目实现：** [services/kg_traversal.py](file:///d:/pythonpro/ollama项目/审计OCR+CPA问答综合系统/services/kg_traversal.py#L251-L292)

```python
def expand_entity(self, entity_id: int, depth: int = 1) -> dict:
    """展开单个实体的邻域（用于可视化）"""
    self.load_graph()
    
    if entity_id not in self._entities:
        return None
    
    entity = self._entities[entity_id]
    entity["id"] = entity_id
    
    result = {
        "entity": entity,
        "neighbors": {
            "incoming": [],  # 入边邻居
            "outgoing": [],  # 出边邻居
        },
    }
    
    # 出边
    for tgt_id, rtype, weight, desc in self._adj_out.get(entity_id, []):
        if tgt_id in self._entities:
            result["neighbors"]["outgoing"].append({
                "entity": {"id": tgt_id, **self._entities[tgt_id]},
                "relation_type": rtype,
                "description": desc,
                "weight": weight,
            })
    
    # 入边
    for src_id, rtype, weight, desc in self._adj_in.get(entity_id, []):
        if src_id in self._entities:
            result["neighbors"]["incoming"].append({
                "entity": {"id": src_id, **self._entities[src_id]},
                "relation_type": rtype,
                "description": desc,
                "weight": weight,
            })
    
    return result
```

**应用场景：**
- 图谱可视化：点击实体后展开关联实体
- 知识导航：从一个概念探索相关知识点

### 2.5 GraphRAG搜索（图增强RAG）

**原理：** 将知识图谱结构融入检索增强生成（RAG）流程，通过图遍历扩展检索范围，提升信息召回质量。

**核心流程：**
1. **实体匹配**：从用户查询中提取关键词，在知识图谱中匹配相关实体
2. **关系扩散**：沿着实体的关系边（出边/入边）扩展，收集相关实体的来源文本
3. **Chunk收集**：从关联实体的source_chunk_ids中提取文本片段作为上下文

**项目实现：** [web_app.py](file:///d:/pythonpro/ollama项目/审计OCR+CPA问答综合系统/web_app.py#L389-L540)

```python
def search_knowledge_base_graph(query, top_k=5, books=None):
    """GraphRAG检索：利用结构化知识图谱（章节树）+ 实体关系扩散"""
    conn = get_db_connection()
    if not conn:
        return []
    try:
        cur = conn.cursor()

        # 1. 用 jieba 分词提取查询中的关键词
        query_words = jieba.cut(query, cut_all=False)
        keywords = [w.strip() for w in query_words
                    if w.strip() and len(w.strip()) >= 2
                    and not re.match(r'^[的了吗是啥我问你]$', w.strip())]
        keywords = list(set(keywords))[:10]

        if not keywords:
            cur.close()
            conn.close()
            return search_knowledge_base(query, top_k=top_k, books=books)

        # 2. 在实体表中搜索匹配的实体
        like_clauses = " OR ".join(["e.name LIKE %s" for _ in range(len(keywords))])
        like_params = [f"%{kw}%" for kw in keywords]

        if books and len(books) > 0:
            book_clauses = " OR ".join(["e.description LIKE %s" for _ in range(len(books))])
            book_params = [f"%{b}%" for b in books]
            cur.execute(f"""
                SELECT e.id, e.name, e.category, e.source_chunk_ids
                FROM cpa_entities e
                WHERE ({like_clauses})
                  AND ({book_clauses})
                ORDER BY
                    CASE e.category
                        WHEN '章' THEN 1
                        WHEN '节' THEN 2
                        WHEN '编' THEN 3
                        ELSE 4
                    END
                LIMIT 20
            """, like_params + book_params)
        else:
            cur.execute(f"""
                SELECT e.id, e.name, e.category, e.source_ids
                FROM cpa_entities e
                WHERE {like_clauses}
                ORDER BY
                    CASE e.category
                        WHEN '章' THEN 1
                        WHEN '节' THEN 2
                        WHEN '编' THEN 3
                        ELSE 4
                    END
                LIMIT 20
            """, like_params)

        entities = cur.fetchall()

        # 3. 收集所有相关 chunk_id
        related_chunk_ids = set()
        matched_entity_ids = set()

        for e in entities:
            eid = e[0]
            matched_entity_ids.add(eid)
            if e[3]:  # source_chunk_ids
                for cid in e[3]:
                    related_chunk_ids.add(cid)

        # 4. 通过关系扩散：找关联实体的 chunk
        if matched_entity_ids:
            id_placeholders = ','.join(['%s'] * len(matched_entity_ids))
            # 找下游实体
            cur.execute(f"""
                SELECT DISTINCT r.target_entity_id, e2.source_chunk_ids
                FROM cpa_relationships r
                JOIN cpa_entities e2 ON e2.id = r.target_entity_id
                WHERE r.source_entity_id IN ({id_placeholders})
                LIMIT 30
            """, list(matched_entity_ids))
            for r in cur.fetchall():
                if r[1]:
                    for cid in r[1]:
                        related_chunk_ids.add(cid)

            # 找上游实体
            cur.execute(f"""
                SELECT DISTINCT r.source_entity_id, e2.source_chunk_ids
                FROM cpa_relationships r
                JOIN cpa_entities e2 ON e2.id = r.source_entity_id
                WHERE r.target_entity_id IN ({id_placeholders})
                LIMIT 30
            """, list(matched_entity_ids))
            for r in cur.fetchall():
                if r[1]:
                    for cid in r[1]:
                        related_chunk_ids.add(cid)

        # 5. 用收集到的 chunk_id 去 cpa_embeddings 查内容
        if related_chunk_ids:
            id_list = list(related_chunk_ids)[:top_k * 3]
            id_placeholders = ','.join(['%s'] * len(id_list))
            cur.execute(f"""
                SELECT e.id, e.chunk_content, e.source_type, e.source_id,
                       0.85 as similarity, e.chunk_summary, e.metadata
                FROM cpa_embeddings e
                WHERE e.id IN ({id_placeholders})
                LIMIT %s
            """, id_list + [top_k])
            graph_rows = cur.fetchall()
        else:
            graph_rows = []

        cur.close()
        conn.close()

        # 6. 如果结构化图谱没有结果，回退到向量检索
        if not graph_rows:
            return search_knowledge_base(query, top_k=top_k, books=books)

        # 构建返回结果
        results = []
        for row in graph_rows:
            meta = None
            try:
                if row[6]:
                    meta = json.loads(row[6]) if isinstance(row[6], str) else row[6]
            except Exception:
                pass
            source_label = ""
            if meta:
                parts = []
                if meta.get("course"): parts.append(meta["course"])
                if meta.get("book"): parts.append(meta["book"])
                if meta.get("heading_path"): parts.append(meta["heading_path"])
                source_label = " > ".join(parts)
            results.append({
                "id": row[0],
                "content": row[1],
                "source_type": row[2],
                "source_id": row[3],
                "similarity": float(row[4]) if row[4] else 0,
                "summary": row[5],
                "metadata": meta,
                "source_label": source_label or f"教材 #{row[3]}"
            })
        return results[:top_k]

    except Exception as e:
        print(f"GraphRAG检索失败: {e}")
        if conn: conn.close()
        return search_knowledge_base(query, top_k=top_k, books=books)
```

**GraphRAG核心步骤详解：**

| 步骤 | 操作 | 图论概念 |
|------|------|----------|
| 1. 关键词提取 | jieba分词提取查询关键词 | - |
| 2. 实体匹配 | 在实体表中搜索匹配实体 | 图节点查询 |
| 3. 初始chunk收集 | 收集匹配实体的source_chunk_ids | 节点属性访问 |
| 4. 关系扩散（下游） | 查找出边连接的实体chunk | 出边遍历 |
| 5. 关系扩散（上游） | 查找入边连接的实体chunk | 入边遍历 |
| 6. chunk查询 | 根据收集的chunk_id查询内容 | 子图信息聚合 |
| 7. 回退机制 | 若无结果回退到向量检索 | 容错设计 |

**GraphRAG的优势：**
- **语义关联**：不仅匹配关键词，还能通过关系发现间接相关的知识
- **上下文扩展**：通过实体关系网络扩展检索范围
- **结构化增强**：利用知识图谱的结构化信息提升检索准确性

```python
        "id": r[0], "label": r[1], "member_count": r[2] or 0,
        "summary": r[3], "keywords": r[4], "modularity": float(r[5]) if r[5] else 0,
    } for r in cur.fetchall()]
    cur.close()
    conn.close()
    return jsonify({"success": True, "communities": communities})
```

**社区发现的意义：**
- 知识聚类：将相关知识点组织成知识模块
- 学习路径：按社区推荐学习顺序
- 知识结构：揭示知识体系的内在结构

### 3.2 力导向布局（Force-Directed Layout）

**原理：** 模拟物理系统中的力，使节点根据力的作用自动排列。

**力模型：**
- **斥力（Repulsion）**：节点之间相互排斥，避免重叠
- **引力（Attraction）**：相邻节点相互吸引，保持连接
- **向心力（Gravity）**：节点趋向于画布中心

**项目实现：** [templates/kg_explorer.html](file:///d:/pythonpro/ollama项目/审计OCR+CPA问答综合系统/templates/kg_explorer.html#L231-L252)

```javascript
function renderGraph(nodes, links) {
    const option = {
        backgroundColor: '#0f1923',
        series: [{
            type: 'graph', 
            layout: 'force',  // 力导向布局
            roam: true,      // 允许缩放和平移
            draggable: true, // 允许拖拽
            force: { 
                repulsion: 300,     // 斥力强度
                edgeLength: [150, 300],  // 边长度范围
                gravity: 0.1,       // 向心力强度
            },
            data: nodes.map(n => ({
                id: n.id, name: n.name, category: n.category,
                symbolSize: n.symbolSize,
                itemStyle: { color: TYPE_COLORS[n.category] || '#999' },
            })),
            links: links.map(l => ({
                source: l.source, target: l.target,
                label: l.label,
                lineStyle: { color: '#4a6a8a', curveness: 0.1, width: 1 },
            })),
            categories: Object.entries(TYPE_COLORS).map(([name, color]) => ({name, itemStyle: {color}})),
            label: { show: true, fontSize: 12, color: '#ccc' },
        }],
    };
    chart.setOption(option, true);
}
```

**力导向布局的优势：**
- 自动布局：无需手动指定节点位置
- 直观展示：相关节点自然聚集
- 交互友好：支持拖拽、缩放

## 5. 算法复杂度分析

### 5.1 BFS复杂度

| 操作 | 时间复杂度 | 空间复杂度 |
|------|-----------|-----------|
| 初始化 | O(1) | O(V) |
| 节点入队 | O(V) | O(V) |
| 边遍历 | O(E) | O(E) |
| **总计** | **O(V + E)** | **O(V + E)** |

### 5.2 双向BFS复杂度

| 操作 | 时间复杂度 | 空间复杂度 |
|------|-----------|-----------|
| 单向搜索 | O(b^(d/2)) | O(b^(d/2)) |
| 双向搜索 | O(b^(d/2)) | O(b^(d/2)) |
| **总计** | **O(b^(d/2))** | **O(b^(d/2))** |

其中：
- b = 平均分支因子（每个节点的平均邻居数）
- d = 最短路径长度

### 5.3 子图展开复杂度

| 操作 | 时间复杂度 | 空间复杂度 |
|------|-----------|-----------|
| 出边遍历 | O(out_degree) | O(out_degree) |
| 入边遍历 | O(in_degree) | O(in_degree) |
| **总计** | **O(degree)** | **O(degree)** |

### 5.4 GraphRAG复杂度

| 步骤 | 时间复杂度 | 说明 |
|------|-----------|------|
| 关键词提取 | O(n) | n = 查询长度 |
| 实体匹配 | O(k * V) | k = 关键词数量 |
| 关系扩散 | O(E) | 遍历相关边 |
| Chunk查询 | O(C) | C = chunk数量 |
| **总计** | **O(k*V + E + C)** | - |
