# 并发向量化配置说明

## 一、架构概述

导入脚本（`import_all_cpa.py`）采用**三阶段流水线架构**，将章节解析、向量生成、数据库写入三个阶段解耦，实现真正的异步并发。

## 二、三阶段流程

### 第一阶段：章节收集

```
输入：Markdown文件
处理：解析章节、切分文本块
输出：[(chapter_id, [text_chunk_1, text_chunk_2, ...]), ...]
特点：纯CPU操作，单线程顺序执行
```

### 第二阶段：并发向量化（核心并发阶段）

```
输入：扁平化后的文本块列表（如 8500 个）
方式：asyncio + aiohttp 异步HTTP请求
限制：Semaphore(6) 控制最大并发数
输出：[(idx, text, vector_1024d), ...]
特点：真正的6并发，IO等待不阻塞
```

### 第三阶段：数据库写入

```
输入：向量化结果列表
方式：单线程顺序写入
特点：保证数据一致性，每500条显示进度
```

## 三、并发配置参数

### 3.1 核心参数

| 参数 | 位置 | 默认值 | 说明 |
|------|------|--------|------|
| `max_concurrent` | `batch_get_embeddings()` | 6 | 最大并发请求数 |
| `timeout` | `async_get_embedding()` | 120秒 | HTTP请求超时时间 |
| `retry` | `async_get_embedding()` | 3次 | 失败重试次数 |

### 3.2 文本切分配置


## 四、并发机制详解

### 4.1 技术选型

| 技术 | 用途 | 说明 |
|------|------|------|
| `asyncio` | 异步事件循环 | Python原生异步框架 |
| `aiohttp` | 异步HTTP客户端 | 非阻塞HTTP请求 |
| `Semaphore` | 并发控制 | 限制同时进行的请求数 |
| `ThreadPoolExecutor` | 进度锁 | 保护共享计数器 |

### 4.2 为什么不用多线程

```
多线程方案：
  ThreadPoolExecutor(6) + requests.get()
  → GIL限制：IO等待时释放GIL，但线程切换有开销
  → 内存开销：每个线程约8MB栈空间

异步方案（当前使用）：
  asyncio + aiohttp
  → 无GIL限制：协程切换极轻量
  → 内存开销：每个协程约几KB
  → 效率更高：无需线程上下文切换
```

### 4.3 并发控制实现

```python
async def batch_get_embeddings(text_chunks, max_concurrent=6, verbose=True):
    semaphore = asyncio.Semaphore(max_concurrent)  # 控制并发数
    
    async def process_with_limit(idx, text):
        async with semaphore:  # 超过max_concurrent时自动等待
            embedding = await async_get_embedding(session, text, model, api_url)
            ...
    
    # 一次性创建所有任务（如8500个）
    tasks = [process_with_limit(i, chunk) for i, chunk in enumerate(text_chunks)]
    # 并发执行，最多同时运行 max_concurrent 个
    results = await asyncio.gather(*tasks)
```

## 五、性能调优

### 5.1 并发数调整

```python
# 根据硬件配置调整 max_concurrent 参数

# CPU核心数 4-6  -> max_concurrent=4
# CPU核心数 8-12 -> max_concurrent=8
# CPU核心数 16+  -> max_concurrent=12

flat_results = asyncio.run(
    batch_get_embeddings(flat_texts, max_concurrent=6, verbose=True)
)
```

### 5.2 文本块大小调整

| chunk_size | 优点 | 缺点 |
|------------|------|------|
| 300 | 检索精度高 | 向量数量多，处理慢 |
| 600（默认） | 平衡性能与精度 | - |
| 1000 | 向量数量少 | 检索精度下降 |

### 5.3 重叠度调整

| chunk_overlap | 作用 |
|---------------|------|
| 0 | 无重叠，可能丢失上下文边界信息 |
| 100（默认） | 少量重叠，保持上下文连贯 |
| 200 | 更多重叠，重复内容增多 |

## 九、常见问题

### Q: 为什么GPU使用率不高？
A: Ollama默认使用CPU，需配置 `OLLAMA_CUDA=1` 环境变量启用GPU加速。

### Q: 并发数设置多大合适？
A: 建议设置为CPU核心数的1-2倍。6并发适合8核心CPU。

### Q: 如何处理请求失败？
A: 内置3次自动重试机制，失败后自动跳过该文本块。
