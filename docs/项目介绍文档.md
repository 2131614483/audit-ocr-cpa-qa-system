# 智审AI — 审计OCR + CPA知识库问答综合系统

## 项目介绍文档

---

## 一、项目背景

### 1.1 行业痛点

在审计实务与CPA（注册会计师）考试备考中，长期存在以下核心痛点：

| 痛点 | 描述 |
|------|------|
| **票据处理效率低** | 传统审计工作中，大量凭证、发票需要人工逐张审验，耗时耗力且极易因疲劳导致错漏 |
| **知识检索困难** | CPA考试涵盖会计、审计、税法、经济法、财管、战略六大科目共23本教材，知识点分散，传统搜索难以精准定位 |
| **经验传承断层** | 资深审计人员的专业判断经验难以系统化沉淀，新人培养周期长 |
| **工具碎片化** | 市面上OCR识别、知识库问答系统各自独立，缺乏审计场景下的整合方案 |

### 1.2 项目目标

本项目旨在构建一个**集审计票据智能识别、知识库检索增强问答（RAG）、批量凭证Agent自动化处理于一体的综合性AI平台**，实现以下目标：

- **自动化**：用AI替代人工完成票据识别、分类、校验的重复劳动
- **智能化**：基于RAG架构的CPA知识库，让AI回答有据可依
- **系统化**：打通"识别 → 校验 → 分析 → 归档"全流程
- **可扩展**：支持多模型供应商切换，灵活适配不同场景需求

## 二、系统总览

### 2.1 系统定位

**智审AI** 是一个面向审计从业人员与CPA考生的综合AI平台，由三大核心子系统构成：

| 子系统 | 服务端口 | 核心能力 | 目标用户 |
|--------|:--------:|----------|----------|
| **审计OCR识别系统** | CLI / 5000端口 | 票据视觉识别、数据校验、风险分析 | 审计从业者 |
| **CPA知识库问答系统** | 5001端口 | RAG智能问答、多模式检索、知识管理 | CPA考生、审计人员 |
| **批量凭证Agent管道** | CLI | 两阶段Agent自动化处理14万+凭证 | 审计机构 |

## 三、核心子系统详解

### 3.1 审计OCR识别系统

#### 3.1.1 功能概述

基于视觉语言模型的票据智能识别系统，支持从图片中自动提取结构化票据信息，并进行数据校验与风险评级。

#### 3.1.2 识别流程

```
┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
│ 图片输入  │──▶│ 主模型    │──▶│ JSON解析  │──▶│ 数据校验  │
│ input_pic │   │ Qwen3.5  │   │ 提取字段  │   │ 8项规则  │
└──────────┘   └──────────┘   └──────────┘   └─────┬────┘
                                                    │
                              ┌──────────┐          │
                              │ DeepSeek │◀──格式错误│
                              │ JSON修复  │          │
                              └─────┬────┘          │
                                    │               ▼
                              ┌──────────┐   ┌──────────┐
                              │ 重试3次   │   │ 风险评级  │
                              │ 仍失败则  │   │ 高/中/低  │
                              │ 使用兜底  │   └─────┬────┘
                              └──────────┘         │
                                                   ▼
                              ┌──────────────────────────┐
                              │     结果输出              │
                              │  ┌────┐ ┌────┐ ┌────┐   │
                              │  │分类 │ │Excel│ │数据库│   │
                              │  │保存 │ │报告 │ │写入 │   │
                              │  └────┘ └────┘ └────┘   │
                              └──────────────────────────┘
```

#### 3.1.3 数据校验规则

系统对OCR识别结果执行8项严格校验：

| 校验项 | 规则说明 |
|--------|----------|
| 日期有效性 | 格式必须为YYYY-MM-DD，且不超过当前日期 |
| 金额有效性 | 支持数字金额和中文大写金额自动转换 |
| 统一社会信用代码 | 18位编码格式校验（含校验码验证） |
| 字段完整性 | 关键字段无缺失 |
| 图像正常性 | 图片可正常读取、无损坏 |
| 重复性检查 | 同批次内无重复票据 |
| 信息一致性 | 各字段间逻辑自洽 |
| 合规性 | 符合审计准则要求 |

#### 3.1.4 异常处理链

```
主模型识别
    ├── 成功 → JSON解析 → 数据校验 → 分类保存/写库
    │
    ├── JSON格式错误 → DeepSeek修复（最多3次）
    │   ├── 修复成功 → 数据校验 → 保存
    │   └── 修复失败 → 兜底JSON（标记为高风险/不通过）
    │
    └── 模型调用失败 → 重试5次（间隔5秒）
        ├── 成功 → 继续流程
        └── 全部失败 → 记录错误日志 → 加入重跑队列
```

### 3.2 CPA知识库问答系统

#### 3.2.1 功能概述

基于RAG（Retrieval-Augmented Generation）架构的CPA考试智能问答平台，已导入23本CPA教材（6大科目），共计4万余个知识块。

#### 3.2.2 已导入教材清单

| 科目 | 教材数量 | 包含内容 |
|:----:|:--------:|----------|
| **会计** | 4本 | 官方教材 + 轻一上册/中册/下册 |
| **审计** | 4本 | 官方教材 + 轻一上册/中册/下册 |
| **税法** | 4本 | 官方教材 + 轻一上册/中册/下册 |
| **经济法** | 4本 | 官方教材 + 轻一上册/中册/下册 |
| **财管** | 4本 | 官方教材 + 轻一上册/中册/下册 |
| **战略** | 3本 | 官方教材 + 轻一上册/下册 |

所有教材均为 **2026年最新版** 内容。

```
│                      │                               │

                       │
```

#### 3.2.4 四种检索模式对比

| 模式 | 技术原理 | 优势 | 劣势 | 适用场景 |
|:----:|----------|------|------|----------|
| **向量** | pgvector余弦相似度 | 语义理解强，能匹配同义表述 | 对罕见专业术语匹配弱 | 概念理解类问题 |
| **BM25** | PostgreSQL tsvector全文检索 | 关键词精确命中 | 无法理解语义 | 特定法条、数字查询 |
| **混合** | 0.7×向量 + 0.3×BM25加权 | 综合最优 | 计算成本稍高 | **默认推荐** |
| **知识图谱** | 实体关系关联检索 | 能进行多跳推理 | 覆盖范围有限 | 知识点关联分析 |

#### 3.2.5 做梦机制（Dream）

「做梦」是本系统独创的知识提炼机制，模拟人类睡眠时巩固记忆的过程：

```
cpa_qa_history（历史问答对）
    │
    │  定时触发 / 手动触发
    ▼
┌────────────────────────────────────────────────────┐
│           run_dream_consolidation()                  │
│                                                      │
│  1. 读取新的历史问答对                                │
│  2. 调用LLM提炼关键知识点（question→key insight）     │
│  3. 与现有梦境知识计算相似度                           │
│  4. 相似度>0.85：合并去重                              │
│  5. 相似度≤0.85：作为新知识点存入                       │
└──────────────────┬─────────────────────────────────┘
                   │
                   ▼
       cpa_dream_knowledge（梦境知识表）
                   │
                   ▼
           供未来RAG检索使用（长期记忆）
```

这一机制使得系统能够从用户的每次问答中持续学习，不断丰富知识储备，越用越智能。

## 五、核心工作流

### 5.1 审计OCR流程（CLI模式）

```
用户执行 python main.py
    │
    ▼
┌──────────────────────────────────────────────────────────────┐
│  1. 初始化日志系统（输出目录、错误日志、重跑队列）               │
│  2. 检查 Ollama 服务状态                                     │
│  3. 扫描 input_pic/ 目录获取图片列表                          │
│  4. 为每张图片：                                              │
│     a. 读取图片 → Base64编码                                  │
│     b. 调用 Qwen3.5:9b 视觉模型 → 获取JSON                    │
│     c. JSON解析 + 字段提取                                    │
│     d. 8项数据校验 → 风险评级                                  │
│     e. 分类保存到 output/分类结果/                             │
│  5. 生成 Excel 汇总报告                                       │
│  6. 写入 PostgreSQL audit_results 表                          │
│  7. 输出统计摘要                                              │
└──────────────────────────────────────────────────────────────┘
```

### 5.2 CPA问答流程（Web模式）

```
用户打开 http://localhost:5001
    │
    ▼
┌──────────────────────────────────────────────────────────────┐
│  1. 用户输入问题 → 点击发送                                   │
│  2. Socket.IO 发送到 /api/chat                                │
│  3. web_app.py 接收请求：                                     │
│     a. search_knowledge_base(query, mode="hybrid")           │
│        → 从 cpa_embeddings 检索 Top-5                         │
│     b. search_qa_history(query)                              │
│        → 从 cpa_qa_history 检索相关历史问答                    │
│     c. 拼接系统Prompt + 检索上下文 + 用户问题                  │
│     d. 调用 DeepSeek API（流式）                               │
│  4. Socket.IO 逐 token 推送到前端                              │
│  5. marked.js 实时渲染 Markdown 格式回答                       │
│  6. 保存问答对到 cpa_qa_history（含向量）                      │
└──────────────────────────────────────────────────────────────┘
```

### 5.3 审计AI辅导（跨服务联动）

```

│                                                              │
│  3. 每个 Agent 接收前序 Agent 的输出作为上下文                  │
│  4. 可配置不同模型（如审计专家用Ollama本地，项目经理用DeepSeek） │
```

## 九、高级特性

### 9.1 知识图谱系统

独立的知识图谱模块，支持从教材中自动抽取实体关系，构建知识点关联网络：

- **实体抽取**：从教材文本中识别概念、定义、公式、法条等实体
- **关系抽取**：提取实体间的"包含"、"关联"、"前置"、"推导"等关系
- **社区检测**：自动发现知识点聚类社区，识别知识领域边界
- **拓扑遍历**：基于图论的关联推理，支持多跳知识推导

API通过 `blueprints/kg_api.py` 的 `/api/kg/*` 路由暴露。

### 9.2 多Agent团队协作

支持定义多个专业化Agent角色，组建协作团队：

```python
# Agent角色示例
agents = [
    {"name": "项目经理", "role": "负责分解审计任务", "model": "deepseek-chat"},
    {"name": "审计专家", "role": "执行具体审计分析", "model": "qwen3.5:9b"},
    {"name": "质控复核", "role": "复核审计底稿质量", "model": "deepseek-chat"}
]

# 通过 orchestrator.run_team_stream() 流式输出团队协作过程
```

### 9.3 中文金额转换

支持将中文大写金额自动转换为数字，兼容简体/繁体：

| 输入 | 输出 |
|------|:----:|
| 壹仟贰佰叁拾肆元伍角陆分 | 1234.56 |
| 壹仟貳佰參拾肆圓伍角陸分 | 1234.56 |
| 零元整 | 0.00 |
| 1234.56 | 1234.56 |

### 9.4 自定义OCR异常处理链

```
主模型识别 → JSON格式校验
    ├── 合法JSON → 数据校验 → 保存
    └── 非法JSON → DeepSeek修复（最多3次）
         ├── 修复成功 → 数据校验 → 保存
         └── 修复失败 → FALLBACK_RESULT（标记高风险）
```

## 十一、常见问题与排错

### 11.1 服务启动问题

| 问题 | 可能原因 | 解决方法 |
|------|----------|----------|
| 端口被占用 | 5000/5001已被其他程序占用 | 修改对应py文件的端口号 |
| Ollama连接失败 | Ollama服务未启动 | 运行 `ollama serve` |
| 模型不存在 | 未下载所需模型 | 运行 `ollama pull <模型名>` |

### 11.2 功能异常

| 问题 | 可能原因 | 解决方法 |
|------|----------|----------|
| 问问AI无响应 | web_app.py未同时运行 | 确保两个服务都启动 |
| 问答回答质量差 | 向量维度不匹配 | 运行 `change_vector_dimension.py` 统一维度 |
| 模态框不显示 | Bootstrap版本冲突 | 使用 `.modal-box` 类名（已规避） |
| 导入教材失败 | pgvector扩展未安装 | `CREATE EXTENSION vector;` |

```bash
# 清空向量库重新导入
python clear_embeddings.py
python import_all_cpa_8b.py

# 切换向量维度
python change_vector_dimension.py 1024   # 轻量模型
python change_vector_dimension.py 4096   # 标准模型

# 检查数据库状态
python check_all_tables.py

# 运行做梦机制（手动）
# 在web_app.py后台触发或直接调用dream_service
```
