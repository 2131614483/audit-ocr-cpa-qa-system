## 一、设计原则

| 原则 | 说明 |
|------|------|
| **独立数据库** | 新建 `cpa_knowledge_graph` 数据库，不碰现有 `cpa_knowledge` |
| **独立表前缀** | 所有新表以 `kg_` 前缀命名，与现有 `cpa_*` 表清晰隔离 |
| **只新增文件** | 不修改任何现有 `.py`、`.sql`、`.html` 文件 |
| **Blueprint挂载** | 通过 Flask Blueprint 注册新路由，不修改 `web_app.py` 现有代码 |
| **新检索模式** | 新增 `graph_v2` 检索模式，与现有 4 种模式和平共存 |
| **回退安全** | 出问题只需删掉新数据库 + 移除 Blueprint 注册，原系统毫发无损 |

## 二、可行性总览

参考文档 `cpa-knowledge-base-tech-stack.md` 提出的知识图谱方案：

| 组件 | 可行性 | 独立实现方式 |
|------|:------:|-------------|
| AI实体/关系抽取 | ✅ | 新建 `services/kg_extractor.py`，DeepSeek API + Few-shot Prompt |
| 图存储 | ✅ | 新建 `cpa_knowledge_graph` 数据库，`kg_entities` + `kg_relationships` 表 |
| 6种关系类型 | ✅ | `kg_relationships.relation_type` 字段，CHECK约束限定6种类型 |
| 易混概念对比 | ✅ | 新建 `kg_confusion_pairs` 表 + 独立抽取逻辑 |
| 公式/计算链 | ✅ | `kg_entities` 增加 `Formula` 类型 + `kg_formulas` 表 |
| 多跳推理 | ✅ | 新建 `services/kg_traversal.py`，BFS/DFS图遍历 |
| 社区检测 | ✅ | 新建 `services/kg_community.py`，Python-igraph实现Leiden |
| 图可视化 | ✅ | 新建 `templates/kg_explorer.html`，ECharts CDN |
| Neo4j | ⚠️ 可延后 | 先用PG，独立DB迁移方便，后续可整体迁Neo4j |
| ChromaDB | ❌ 不需要 | 新建 `kg_entities.embedding` 列用 pgvector，延续现有技术栈 |
| FastAPI | ❌ 不需要 | Flask Blueprint 独立挂载，功能完整 |

### 4.2 独立数据库设计

新建数据库 `cpa_knowledge_graph`，所有表以 `kg_` 前缀命名：

```sql
-- ============================================
-- 数据库: cpa_knowledge_graph
-- 所有表独立于现有的 cpa_knowledge 数据库
-- ============================================

-- 1. 实体表
CREATE TABLE kg_entities (
    id SERIAL PRIMARY KEY,
    name VARCHAR(200) NOT NULL,
    entity_type VARCHAR(30) NOT NULL
        CHECK (entity_type IN ('Concept','Standard','Formula','TaxItem','Question','Chapter','Section')),
    category VARCHAR(50),           -- 会计科目/审计程序/税目税率/财管公式/...
    definition TEXT,                -- 定义
    chapter_ref VARCHAR(200),       -- 所属章节引用（如"会计 > 第5章 长期股权投资"）
    source_chunk_ids INT[],         -- 来源chunk ID (对应cpa_knowledge.cpa_embeddings.id)
    embedding VECTOR(4096),         -- 实体名向量，用于实体链接
    aliases TEXT[],                 -- 别名列表（实体对齐去重用）
    metadata JSONB,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(name, entity_type)
);

-- 2. 关系表
CREATE TABLE kg_relationships (
    id SERIAL PRIMARY KEY,
    source_entity_id INT NOT NULL REFERENCES kg_entities(id) ON DELETE CASCADE,
    target_entity_id INT NOT NULL REFERENCES kg_entities(id) ON DELETE CASCADE,
    relation_type VARCHAR(30) NOT NULL
        CHECK (relation_type IN (
            'derives_from',      -- A的计算依赖B
            'references',        -- A引用准则B
            'contrasts_with',    -- A与B容易混淆
            'prerequisite_of',   -- 学B之前必须先懂A
            'composes',          -- A由B1,B2组成
            'leads_to',          -- A的变动会导致B变动
            'belongs_to',        -- A属于章节B
            'tested_by',         -- A被考题B测试
            'similar_to'         -- A与B相似（跨章节同类概念）
        )),
    description TEXT,             -- 关系说明
    formula TEXT,                 -- 如果是推导关系，存公式
    weight FLOAT DEFAULT 1.0,     -- 关系权重
    confidence FLOAT DEFAULT 0.5, -- LLM抽取置信度
    source_chunk_ids INT[],
    metadata JSONB,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(source_entity_id, target_entity_id, relation_type)
);

-- 3. 公式表
CREATE TABLE kg_formulas (
    id SERIAL PRIMARY KEY,
    entity_id INT REFERENCES kg_entities(id) ON DELETE CASCADE,
    name VARCHAR(200) NOT NULL,
    expression TEXT NOT NULL,       -- 公式表达式
    inputs JSONB,                   -- ["营业收入", "营业成本"]
    output VARCHAR(200),            -- "毛利润"
    conditions TEXT,                -- 适用条件
    example TEXT,                   -- 计算示例
    source_chunk_ids INT[]
);

-- 4. 易混概念对表
CREATE TABLE kg_confusion_pairs (
    id SERIAL PRIMARY KEY,
    entity_a_id INT NOT NULL REFERENCES kg_entities(id) ON DELETE CASCADE,
    entity_b_id INT NOT NULL REFERENCES kg_entities(id) ON DELETE CASCADE,
    distinction TEXT NOT NULL,      -- 区分要点
    typical_question TEXT,          -- 典型考题
    scenario_a TEXT,                -- 概念A的典型使用场景
    scenario_b TEXT,                -- 概念B的典型使用场景
    chapter_ids INT[],
    UNIQUE(entity_a_id, entity_b_id)
);

-- 5. 社区检测结果表
CREATE TABLE kg_communities (
    id SERIAL PRIMARY KEY,
    community_label VARCHAR(100),   -- 社区标签（LLM生成）
    entity_ids INT[],
    summary TEXT,                   -- 社区主题摘要（LLM生成）
    topic_keywords TEXT[],
    modularity_score FLOAT,         -- 模块度得分
    embedding VECTOR(4096),         -- 摘要向量，用于检索
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 6. 图谱构建日志表
CREATE TABLE kg_build_log (
    id SERIAL PRIMARY KEY,
    build_type VARCHAR(30) NOT NULL,  -- entity_extraction / relation_extraction / community_detection
    status VARCHAR(20) DEFAULT 'running',
    chunks_processed INT DEFAULT 0,
    entities_created INT DEFAULT 0,
    relations_created INT DEFAULT 0,
    errors JSONB,
    started_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    finished_at TIMESTAMP
);

-- 索引
CREATE INDEX idx_kg_entities_type ON kg_entities(entity_type);
CREATE INDEX idx_kg_entities_name ON kg_entities USING gin(name gin_trgm_ops);
CREATE INDEX idx_kg_entities_embedding ON kg_entities USING ivfflat (embedding vector_cosine_ops);
CREATE INDEX idx_kg_rel_source ON kg_relationships(source_entity_id);
CREATE INDEX idx_kg_rel_target ON kg_relationships(target_entity_id);
CREATE INDEX idx_kg_rel_type ON kg_relationships(relation_type);
CREATE INDEX idx_kg_communities_embedding ON kg_communities USING ivfflat (embedding vector_cosine_ops);
```

### 4.3 跨库数据流

```
构建阶段:
  cpa_knowledge.cpa_embeddings  ──只读查询──→  kg_extractor.py  ──写入──→  cpa_knowledge_graph.kg_*

检索阶段:
  用户查询
    → 实体链接 (kg_entities 向量匹配)
    → BFS遍历 (kg_relationships 多跳扩散)
    → 收集 source_chunk_ids
    → 跨库查询 cpa_knowledge.cpa_embeddings 取原文内容
    → 融合排序返回
```

**`services/kg_extractor.py` 核心函数**：

```python
class KnowledgeGraphExtractor:
    """
    CPA知识图谱抽取器
    独立于现有代码，只依赖 DeepSeek API + Ollama Embedding
    """

    def __init__(self, graph_db_config: dict, source_db_config: dict):
        """
        graph_db_config: cpa_knowledge_graph 连接配置（写入）
        source_db_config: cpa_knowledge 连接配置（只读）
        """
        self.graph_conn = psycopg2.connect(**graph_db_config)
        self.source_conn = psycopg2.connect(**source_db_config)

    # ---- 四个抽取阶段 ----

    def extract_entities(self, chunk_text: str, metadata: dict) -> list[dict]:
        """
        LLM抽取实体，区分类型。
        Prompt模板见 data/kg_prompts.json → entity_extraction
        返回: [{name, entity_type, category, definition, chapter_ref}]
        """

    def extract_relationships(self, entities: list, chunk_text: str) -> list[dict]:
        """
        LLM抽取关系，6+3种类型。
        Prompt模板见 data/kg_prompts.json → relation_extraction
        返回: [{source, target, relation_type, description, formula?}]
        """

    def extract_formulas(self, chunk_text: str) -> list[dict]:
        """
        LLM抽取计算公式和分录逻辑。
        Prompt模板见 data/kg_prompts.json → formula_extraction
        返回: [{name, expression, inputs, output, conditions, example}]
        """

    def detect_confusion_pairs(self, entities: list, chunk_text: str) -> list[dict]:
        """
        LLM识别易混概念对。
        Prompt模板见 data/kg_prompts.json → confusion_detection
        返回: [{concept_a, concept_b, distinction, typical_question}]
        """

    # ---- 实体对齐 ----

    def deduplicate_entities(self, entities: list) -> list:
        """
        与 kg_entities 已有实体比较：
        1. 精确名称匹配 → 合并 source_chunk_ids
        2. 向量相似度 > 0.92 → 人工审核候选
        3. 编辑距离 < 2 → 合并 + 添加别名
        """

    # ---- 批量处理 ----

    def build_from_chunks(self, book_filter: str = None, limit: int = None,
                          concurrent: int = 5):
        """
        从 cpa_knowledge.cpa_embeddings 读取 chunk
        → 逐 chunk 抽取
        → 去重对齐
        → 写入 cpa_knowledge_graph.kg_*
        → 记录日志到 kg_build_log
        """
```

**`services/kg_traversal.py` 核心函数**：

```python
class GraphTraverser:
    """图遍历引擎"""

    def bfs(self, start_ids: list, max_depth: int = 3,
            relation_types: list = None) -> list[dict]:
        """
        BFS遍历。
        返回: [{entity_id, name, depth, path: [(from_entity, relation_type, to_entity), ...]}]
        支持按关系类型过滤（如只看 leads_to + derives_from 做因果推理）
        """

    def find_paths(self, source_id: int, target_id: int,
                   max_depth: int = 5) -> list[dict]:
        """双向BFS找两个实体间的最短路径"""

    def expand_entity(self, entity_id: int, depth: int = 1) -> dict:

| 查询类型 | 示例 | 纯向量检索 | 图检索(v2) |
|----------|------|-----------|-----------|
| 概念定义 | "什么是长期股权投资？" | ✅ 能找到 | ✅ 更快（直接实体匹配） |

## 六、技术选型建议

| 决策点 | tech-stack文档建议 | 本方案 | 理由 |

| 后端框架 | FastAPI | **Flask Blueprint** | 不重写，挂载即可 |

## 七、风险和成本

### 7.1 风险

| 风险 | 概率 | 缓解措施 |
|------|:----:|----------|
| LLM抽取质量不稳定 | 中 | Few-shot Prompt + 人工抽检前100条 + confidence字段记录置信度 |
| 实体对齐去重不准 | 中 | 精确名匹配 + 向量相似度(>0.92) + 编辑距离 + 人工审核接口 |
| 图检索性能随规模下降 | 低 | BFS限制max_hops=3；结果上限50；已建好索引 |
| 跨库查询延迟 | 低 | cpa_embeddings.id直接查询，走主键索引；也可定期将top-chunk摘要同步到新库 |
| DeepSeek API费用 | 低 | 六科约3000万input tokens，约¥30；可分批，先跑一科验证 |

### 7.2 成本预估

| 资源 | 预估量 | 说明 |
|------|--------|------|
| LLM Token消耗 | ~500万 input / 科 | 六科约3000万tokens，DeepSeek约¥30 |
| 新增存储 | PG 100-500MB | kg_* 六张表 |
| 开发时间 | 约2周 | Phase 1-6，含验证和调优 |

### 7.3 回退方案

出问题只需两步回退：

psql -U postgres -c "DROP DATABASE cpa_knowledge_graph;"

# 2. 注释掉 web_app.py 中的 Blueprint 注册行（或改用独立启动脚本则直接停掉）
# from blueprints.kg_api import kg_bp         ← 注释
# app.register_blueprint(kg_bp)               ← 注释
```

原系统毫发无损。
